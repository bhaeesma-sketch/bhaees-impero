## 2023-10-27 - Auth Form State Bleed and AutoComplete UX
**Learning:** When using components like `<Tabs>` or toggle buttons to switch between "Login" and "Register" forms that share state variables (e.g., `username`, `password`), state bleed occurs. This can cause confusing user experiences, such as accidentally submitting a login attempt with a partially typed registration password. Additionally, modern browsers heavily rely on `autoComplete` attributes (`username`, `current-password`, `new-password`) to offer appropriate autofill and password generation, which fail silently or behave unpredictably when missing or on toggled shared forms.
**Action:** Always add an explicit state clearing handler (e.g., `onValueChange` for Tabs or within `onClick` for toggle buttons) to reset shared state variables when the view switches. Ensure all auth-related input fields include the proper `autoComplete` attributes, conditionally changing them if the same input element is reused for both login and registration (e.g., `autoComplete={isLogin ? "current-password" : "new-password"}`).

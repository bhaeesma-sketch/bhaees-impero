## 2024-05-24 - Shared Component State Bleed & Auth Accessibility
**Learning:** When using shared component states (like `username` and `password`) across different views within the same component (such as Radix UI `<Tabs>` or conditional toggles in Modals), state bleeds over when the user switches views. This can lead to confusing UX where a user's input from the "Login" tab remains filled when they switch to the "Register" tab. Additionally, native authentication forms need explicit `autoComplete` attributes (`username`, `current-password`, `new-password`) to ensure proper accessibility and compatibility with browser password managers.
**Action:** Always implement explicit state reset handlers on view-switching events (like `onValueChange` for Tabs or `onClick` for toggle buttons) when forms share the same state variables. Always add appropriate `autoComplete` and `required` attributes to authentication inputs.

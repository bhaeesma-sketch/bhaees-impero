## 2026-05-03 - Prevent State Bleed in Shared Forms
**Learning:** When using components that toggle between views with shared form state (like Radix `<Tabs>` for Login/Register or modals that can be closed and reopened), the state "bleeds" over unless explicitly cleared. A user who types a username into "Login" and switches to "Register" will see that same username pre-filled, which can lead to unintentional registrations or confusing errors. Modals present a similar issue: if closed mid-typing, the state persists when re-opened.
**Action:** Always add an `onValueChange` handler to Radix `<Tabs>` to reset shared state variables (e.g., `setUsername('')`). For modals, clear state during `onOpenChange` when the modal is closed (`open === false`). For custom toggle buttons, attach state-clearing logic to the `onClick` handler alongside the view toggle.

## 2024-04-22 - Prevent Form State Bleed and Enhance A11y
**Learning:** In React components featuring shared state across multiple views (like a toggleable login/register form using `<Tabs>` or a button), the state (e.g., `username`, `password`) bleeds over when switching views. This leads to a confusing UX where data typed in the login form persists into the register form. Additionally, adding correct `autoComplete` attributes is vital for a11y and UX in authentication forms.
**Action:** Always implement an `onValueChange` handler on `<Tabs>` components (or `onClick` handlers on toggle buttons) to clear shared form state (`setUsername('')`, `setPassword('')`) when the view changes. Simultaneously, explicitly define `autoComplete` attributes (`username`, `current-password`, `new-password`) along with `required` properties on all form inputs.

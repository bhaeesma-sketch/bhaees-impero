## 2024-05-24 - Shared State Bleed in Authentication Forms
**Learning:** When using Radix UI `<Tabs>` or custom toggle buttons to switch between Login and Register views that share state variables (like `username` and `password`), state bleed occurs on view switch. For example, a password typed in the Login tab will persist in the Register tab if the user switches before submitting. Additionally, adding proper `autoComplete` attributes (e.g., `username`, `current-password`, `new-password`) and native `required` validation on inputs greatly improves the UX and password manager support.
**Action:** Add an explicit `onValueChange` handler to the `<Tabs>` component or the toggle button's `onClick` to clear shared state when switching views. Always include `required` and the corresponding `autoComplete` attributes for authentication inputs.
